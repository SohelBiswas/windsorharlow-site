Architecture walkthrough+

Upload directly

The client requests a temporary upload URL through Django, then uploads file bytes directly to the raw S3 bucket. The later completion request records the document and enqueues processing; the file itself does not pass through the API pods.

Process in the background

Separate SQS queues feed ingest, transform, notification and reporting workers. Workers read raw files from S3, write derived artifacts and metadata, and retry safely using recorded processing steps. Celery Beat schedules reports and maintenance.

Read and persist

RDS PostgreSQL stores document metadata through PgBouncer. Reads check ElastiCache Redis first and fall back to the RDS read replica. Redis also holds task results; SQS remains the durable work broker.

Scale and operate

HPA follows API CPU demand, KEDA follows queue depth, and Karpenter responds to pending pods. CloudWatch, Prometheus and Grafana expose application and infrastructure signals for incident runbooks and resource reviews.

The engineering

Decisions that
shape the system.

A document-processing platform that keeps each organisation’s records separate. Files upload directly to Amazon S3, while queued background jobs validate documents, extract text, create previews and notify connected systems. The application runs on Amazon EKS with autoscaling and operational runbooks.

01Keep uploads out of the API+

Django issues a temporary S3 upload URL. The client sends the file directly to S3, then confirms completion through the API. This keeps file bytes off the API pods while preserving tenant-scoped document records.

02Give each workload its own queue+

Ingest, transform, notification and reporting jobs use separate SQS queues and Celery workers. Repeated deliveries are safe to retry through recorded processing steps; failed jobs move to dead-letter queues for investigation.

03Operate the whole path+

HPA scales the API, KEDA responds to queued work, and Karpenter supplies node capacity. PgBouncer manages database connections, Redis supports cached reads and task results, and metrics, load tests and failure scenarios support operational runbooks.
