Accessibility Test Framework

Automated accessibility checks that turn every issue into a report a non-engineer can act on.

ClientEngagementClientTypeTest frameworkOutputJSON → HTML report
Overview · Quality engineering

Accessibility, made actionable.

A tool that checks web pages for accessibility issues and groups the findings in a browser-based report. It uses Java, Selenium, Cucumber and Deque Axe for the checks, with React for reporting.

The Engineering

Decisions that shape the system.

01

Scanning inside the test suite

Deque Axe runs against real pages driven by Selenium, so accessibility is checked on the rendered page in the same run as every other test.

02

Scenarios in plain English

Cucumber keeps each check readable as a sentence, so the suite doubles as documentation of what is being enforced.

03

A report for the whole team

The JSON output is transformed into a React interface grouping issues by severity and by page — readable without opening a terminal.

Capabilities

What it does.

Rule-based scanning

Axe checks the rendered page, not the source.

Plain-English tests

Each scenario reads as a sentence in Gherkin.

Grouped by severity

Critical to minor, and by page.

Element-level detail

Every finding names the element and the rule.

Browser-based report

Opens as a page, not a terminal dump.

Fits into CI

Runs with the rest of the suite on every build.
